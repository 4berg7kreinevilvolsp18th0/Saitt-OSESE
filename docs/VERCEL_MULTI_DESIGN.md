# Несколько дизайнов: отдельные Next.js-приложения и Vercel

В репозитории три независимых фронтенда (каждый со своим `package.json` и сборкой):

| Вариант | Папка (Root Directory в Vercel) | Отличие |
|--------|-----------------------------------|---------|
| Базовый (основной) | `frontend/nextjs` | Тёмная тема по умолчанию, переключение светлой/тёмной и сезонная зимняя тема как в коде. |
| Светлый брендбук | `frontend/nextjs-design-light` | Зафиксированы классы `light` и `light-brandbook` на `<html>`, тема в `lib/theme.ts` всегда светлая. |
| Зимний акцент | `frontend/nextjs-design-winter` | На `<html>` заданы `winter-theme`, `winter-theme-brandbook`, `dark`; зимние классы включаются при монтировании в `ThemeProvider`. |

Пользователь изначально выбрал **custom** набор вариантов; пока зафиксированы два дополнительных деплоя (светлый и зимний) поверх базового. Новые варианты можно добавить копированием `frontend/nextjs` в `frontend/nextjs-design-<slug>` и правками темы в `app/layout.tsx` / `lib/theme.ts` / `components/ThemeProvider.tsx`.

## Деплой на Vercel (один репозиторий — несколько проектов)

Для **каждого** варианта создайте отдельный проект в Vercel:

1. **Add New Project** → выберите этот Git-репозиторий.
2. В настройках проекта укажите **Root Directory** на одну из папок из таблицы выше.
3. **Environment Variables**: скопируйте с действующего прод-проекта (Supabase, NextAuth, `NEXT_PUBLIC_*`, Postgres/Redis и т.д.). Имена и значения должны совпадать, если все варианты ходят в одни и те же бэкенды.
4. При необходимости задайте **отдельный домен** или поддомен для каждого проекта (например `preview-light.example.com`).

Автоматический деплой из этой среды без вашего аккаунта Vercel невозможен: используйте веб-интерфейс Vercel или локально `vercel` CLI после `vercel login`.

## Локальная проверка

В каталоге выбранного варианта:

```bash
cd frontend/nextjs-design-light
npm install
npm run build
```

Повторите для `frontend/nextjs-design-winter` и при необходимости для `frontend/nextjs`.

## Синхронизация кода между вариантами

Сейчас варианты — **полные копии** кода. После изменений в «эталоне» (`frontend/nextjs`) переносите правки вручную или через diff/merge в папки `nextjs-design-*`. Долгосрочно можно вынести общий код в `packages/` внутри монорепозитория (отдельная задача).
